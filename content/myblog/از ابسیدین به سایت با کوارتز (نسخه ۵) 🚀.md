## کوارتز چیه؟

![[attachments/c31b55a82b7909b0ae929b2e370a2707_MD5.png]]

کوارتز یک Static Site Generator رایگان است. سایتی که الان جلوی روی شماست، با کوارتز ساخته شده. به زبان ساده، **کوارتز یادداشت‌های ابسیدین را به عنوان ورودی می‌گیرد و به عنوان خروجی، یک سایت تحویل می‌دهد.** به نظر من برای کسی که دنبال برنامه‌نویسی و سایت‌سازی از صفر نیست، کوارتز بهترین گزینه است. به خصوص که کوارتز جایزهٔ بهترین ابزار ابسیدین را هم گرفته است.

برای آشنایی بیشتر، قبل از شروع، این چند سایت را ببینید که با کوارتز ساخته شده‌اند:

- **[بلاگ کریستالین] ([blog.eledah.ir](https://blog.eledah.ir/))**
- [وبلاگ فرد](https://ifard.ir/) (وطنی)
- [سایت کوارتز](https://quartz.jzhao.xyz/)

### کوارتز در برابر راه‌های مشابه

کوارتز تنها Static Site Generator موجود نیست. **Hugo**، **Jekyll**، **MkDocs** و کلی سایت‌ساز رایگان دیگر هم در بازار موجودند. علاوه بر اینها، سینک کردن با وردپرس هم ممکن است. خود ابسیدین هم سرویسی به نام **Publish** دارد که یک سایت از Vault شما می‌سازد؛ اما به دلیل اینکه ماهی ۸ تا ۱۰ دلار برای کاربر عادی ایرانی آب می‌خورد، چندان به صرفه نیست. پس به جای راه گرانِ ساده، سراغ راه رایگانی می‌رویم که یک‌کم سخت‌تر است. البته نه خیلی. پیش‌بینی من از زمان راه‌اندازی کوارتز بین **۴۵ تا ۶۰ دقیقه** است. بعد از راه‌اندازی هم هر بار خیلی راحت با یک دستور ساده سایت خودبه‌خود آپدیت می‌شود.

حالا چرا کوارتز؟ دلیل اصلی این است که **سازنده‌اش آن را به تن ابسیدین دوخته**. یعنی خودش کاربر ابسیدین بوده و کوارتز را برای انتشار آنلاین یادداشت‌هایش ساخته. آپدیت‌هایی که در آینده به آن اضافه می‌شود، در جهت نزدیکی بیشتر به تجربهٔ ابسیدین است. باقی سرویس‌ها توانایی تبدیل یادداشت به سایت را دارند؛ اما توجهی به ریزه‌کاری‌ها و جزئیات ابسیدین —مثل لینک‌های داخلی، استفاده از بک‌لینک یا برچسب، جستجوی حرفه‌ای و…— ندارند. تنظیم این ابزارها وقت و مهارت برنامه‌نویسی می‌خواهد. پس بهتر است سراغ ابزاری برویم که بیشترین همخوانی را با ابسیدین دارد.

> [!tip] راه ساده‌تر
> اگر به دنبال آموزش ساده‌تر و سریع‌تری هستید، **مطلب میانبر سایت‌سازی با کوارتز** در سایت کریستالین را ببینید. با راه میانبر از روی خیلی از قدم‌های پایین می‌پرید و سریع‌تر به سایت می‌رسید. این راه را به‌ویژه به افرادی که سابقهٔ هیچ‌گونه برنامه‌نویسی ندارند توصیه می‌کنم.

## ۰. پیش‌نیازها

انجام این پیش‌نیازها پیچیدگی خاصی ندارد؛ اما اگر به مشکل خوردید، از آموزش‌های فارسی آنلاین استفاده کنید یا از دوستان برنامه‌نویس بپرسید.

| ابزار | کاربرد |
|-------|--------|
| **Node.js** (حداقل v20) | نصب، اجرا و تست سایت |
| **Git** | دریافت کوارتز و به‌روزرسانی سایت |
| **VSCode** (اختیاری) | ویرایش کد و ترمینال |
| **اکانت گیتهاب** | میزبانی سایت |

### اطمینان از نصب

برای اینکه از نصب Node.js و Git مطمئن شوید، این دستورات را داخل ترمینال (CMD) اجرا کنید:

```bash
node -v
npm -v
git --version
```

در صورتی که ارور خاصی مشاهده نشد و صرفاً عدد ورژن را دیدید، یعنی نصب با موفقیت انجام شده است. ✅

> [!info] ورژن‌های موردنیاز
> برای راه‌اندازی کوارتز باید ورژن Node.js حداقل **v20** و ورژن npm حداقل **v9.3.1** باشد. آخرین نسخه‌های لازم را با سایت رسمی کوارتز چک کنید.

## ۱. راه‌اندازی کوارتز

اول از همه با کوارتز یک نسخهٔ محلی —نه اینترنتی— از سایتمان می‌سازیم تا در مرحله‌های بعدی آن را در قالب یک سایت اینترنتی بالا بیاوریم.

### گام ۱: دانلود کد کوارتز

دستور پایین را در ترمینال اجرا کنید تا کد کوارتز در دستگاه شما کپی شود. هرجایی که این کد اجرا شود، یک پوشه با نام `quartz` به همراه کدهای مورد نیازش ایجاد می‌شود.

```bash
git clone https://github.com/jackyzha0/quartz.git
```

> [!warning] ارور به خاطر فیلترینگ
> اگر اجرای کد بالا یا هر کد دیگری که اطلاعات را دانلود و آپلود می‌کند با خطا مواجه شد، ممکن است به خاطر تنظیمات اینترنت شما باشد. اگر فیلترشکن روشن است، خاموشش کنید یا برعکس.

### گام ۲: ورود به پوشه و نصب وابستگی‌ها

پوشهٔ کوارتز را با این دستور باز کنید:

```bash
cd quartz
```

سپس با دستور `npm i` نیازمندی‌های کوارتز را نصب کنید:

```bash
npm i
```

اگر حین اجرای دستور بالا با ارور یا هشدار خاصی مواجه شدید، محض محکم‌کاری دستور پایین را هم اجرا کنید که همهٔ نیازمندی‌ها نصب شوند:

```bash
npm audit fix --force
```

### گام ۳: ساخت پروژهٔ کوارتز

```bash
npx quartz create
```

> [!note] تفاوت مهم با نسخهٔ ۴ 🆕
> در نسخهٔ ۵، اول از شما می‌پرسد کدام **قالب (Template)** را می‌خواهید. گزینهٔ **Obsidian** را انتخاب کنید:
> ```
> ◆  Choose a template for your Quartz configuration
> │  ○ Default
> │  ● Obsidian        ← این را انتخاب کنید
> │  ○ TTRPG
> │  ○ Blog
> ```

سپس سؤال‌های بعدی:

**سؤال ۱ — مقداردهی محتوا:**
```
Choose how to initialize the content
│  ● Empty Quartz        ← Enter بزنید
│  ○ Copy an existing folder
│  ○ Symlink an existing folder
```

**سؤال ۲ — آدرس سایت (baseUrl):**
```
◆  Enter the base URL for your Quartz site
│  USERNAME.github.io/REPONAME
```

> [!warning] بدون `https://` و بدون `/` در آخر بنویسید. مثلاً: `zaadpro.github.io/myblog`

**سؤال ۳ — مدل لینک‌ها:** اگر مطمئن نیستید، اولی را انتخاب کنید. در غیر این‌صورت به بخش `Files and links` تنظیمات ابسیدین مراجعه کنید و ببینید جلوی `New link format` قبلاً چه تنظیماتی را انتخاب کرده‌اید.
```
Choose how Quartz should resolve links in your content
│  ● Treat links as shortest path
│  ○ Treat links as absolute path
│  ○ Treat links as relative path
```

> [!note] تفاوت مهم 🆕
> در نسخهٔ ۵، فایل پیکربندی **`quartz.config.yaml`** است (نه `quartz.config.ts` که در نسخهٔ ۴ بود). این نکته را تا آخر مطلب به خاطر بسپارید.

### گام ۴: تست محلی

تبریک! با تعیین تکلیف این موارد، سایت شما آماده است. حالا با اجرای دستور زیر، سایت شما ساخته می‌شود:

```bash
npx quartz build --serve
```

اگر همه‌چیز درست پیش رفته باشد، با رفتن به آدرس `http://localhost:8080` در مرورگر باید نسخهٔ اولیهٔ سایت خودتان را ببینید.

![[attachments/f2bd568322443354d25e9a04ae03fe13_MD5.png]]

> [!info] فایل‌های سایت
> فایل‌های HTML سایتی که کوارتز برای شما ساخته است، در پوشهٔ `public` قابل مشاهده است.

> [!warning] پذیرفتن درخواست فایروال
> در این مرحله ممکن است فایروال سیستم‌عامل شما درخواستی برای اجازه دادن یا ندادن به Node برای انجام یک سری عملیات بکند. حواستان باشد که با این درخواست **موافقت** کنید.

**متوقف کردن کوارتز:** تا وقتی که ترمینال باز است، کوارتز هم اجرا می‌شود. برای توقف، در ترمینال **Ctrl + C** را بزنید، سپس یک `y` جلویش بنویسید و Enter بزنید.

## ۲. اتصال کوارتز به گیتهاب

تا اینجای کار سایت ساخته شده، منتها آنلاین و روی اینترنت نیست؛ فقط در دستگاه شماست. حالا می‌خواهیم این سایت را جایی بگذاریم که بشود با هر دستگاه متصل به اینترنت آن را دید.

### گام ۱: ساخت Repository

بعد از اینکه اکانت خودتان را در گیتهاب ساختید، با کلیک روی دکمهٔ **+** در سمت بالا راست صفحه و انتخاب `New repository` یک Repo جدید بسازید. برای اسم این Repo هر چه دوست داشتید —مثل `blog` یا `myblog` یا `website`— انتخاب کنید. تیکِ `Add a README file` را بردارید و بدون تغییر باقی تنظیمات، `Create Repository` را بزنید.

### گام ۲: اتصال کوارتز به Repo خودتان

دوباره به ترمینال برگردید و این دستور را اجرا کنید:

```bash
git remote rm origin
```

> [!note] اگر ارور `No such remote: 'origin'` داد، مشکلی نیست. یعنی از قبل remote ای نبوده. مستقیم بروید سراغ دستور بعدی.

و بعد این:

```bash
git remote add origin https://github.com/USERNAME/REPONAME.git
```

> [!warning] حواستان باشد که در کد بالا، مقادیر `USERNAME` و `REPONAME` را با نام کاربری و اسم انتخابی Repo خودتان جایگزین کنید.

**این دو دستور چیکار می‌کنند؟** در حالت عادی، فایل کوارتزی که دانلود کرده‌اید به اکانت سازندهٔ اصلی‌اش متصل است. دستور اول این اتصال را قطع می‌کند و دستور دوم فایل‌های روی کامپیوتر را به اکانت خودتان متصل می‌کند.

### گام ۳: معرفی خودتان به Git

> [!danger] خیلی مهم!
> اگر این کار را نکنید، بعداً موقع sync با ارور `Please tell me who you are` مواجه می‌شوید و **commit ساخته نمی‌شود** (یعنی تغییرات هرگز به گیتهاب نمی‌رسند و سایت آپدیت نمی‌شود).

```bash
git config --global user.email "ایمیل‌تان@example.com"
git config --global user.name "نام‌تان"
```

### گام ۴: آپلود فایل‌ها روی گیتهاب

```bash
npx quartz sync --no-pull
```

بعد از سینک شدن فایل‌ها، اگر مشکلی پیش نیامده باشد، کوارتز در فضای ترمینال یک `Done` به نشانهٔ پایان کار به شما نشان می‌دهد. ✅

## ۳. بالا آوردن سایت با گیتهاب

تا اینجای کار، کد کوارتز روی گیتهاب رفته است. حالا باید به گیتهاب بگوییم که سایت آنلاین را برای ما بسازد.

### گام ۱: ساخت فایل deploy.yml

به پوشهٔ زیر در فایل‌های کوارتز بروید و یک فایل با عنوان `deploy.yml` بسازید:

```
.github/workflows/
```

> [!note] مخفی بودن پوشه
> پوشهٔ `.github` ممکن است در کامپیوتر شما مخفی باشد. در File Explorer ویندوز، از تب **View** تیک **Hidden items** را بزنید.

داخل فایل `deploy.yml`، کد پایین را Paste و سپس آن را ذخیره کنید.

> [!danger] تفاوت حیاتی با نسخهٔ ۴ 🆕
> در نسخهٔ ۵، deploy.yml باید شامل مرحلهٔ **نصب پلاگین‌ها** (`npx quartz plugin install`) باشد و از **Node 24** و **actions v6** استفاده کند. بدون این مرحله، build در گیتهاب **شکست می‌خورد** (ارور `exit code 1`)، چون محیط گیتهاب خالی است و پلاگین‌های کوارتز ۵ در آن نصب نیستند. همچنین مقدار `branches` باید **`v5`** باشد (برای اطمینان، دستور `git branch` را بزنید).

```yaml
name: Deploy Quartz site to GitHub Pages

on:
  push:
    branches:
      - v5

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v6
        with:
          node-version: 24
      - name: Cache dependencies
        uses: actions/cache@v5
        with:
          path: ~/.npm
          key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
          restore-keys: |
            ${{ runner.os }}-node-
      - name: Cache Quartz plugins
        uses: actions/cache@v5
        with:
          path: .quartz/plugins
          key: ${{ runner.os }}-plugins-${{ hashFiles('quartz.lock.json') }}
          restore-keys: |
            ${{ runner.os }}-plugins-
      - name: Install Dependencies
        run: npm ci
      - name: Install Quartz plugins
        run: npx quartz plugin install
      - name: Build Quartz
        run: npx quartz build
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: public

  deploy:
    needs: build
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

### گام ۲: تنظیم GitHub Pages

به صفحهٔ Repo خودتان در سایت گیتهاب برگردید. داخل `Settings` بروید و از منوی سمت چپ `Pages` را انتخاب کنید. و برای `Source` گزینهٔ `GitHub Actions` را بزنید.

![[attachments/d8181de7493cc609e77093f0a29a5f80_MD5.jpg]]

### گام ۳: سینک نهایی

حالا با اجرای دستور زیر، یک دور دیگر محتویات کوارتز را با گیتهاب سینک می‌کنیم و گیتهاب سایت را برای ما می‌سازد:

```bash
npx quartz sync
```

بعد از چند دقیقه که گیتهاب سایت را ساخت، با مراجعه به این آدرس سایتتان را ببینید:

```
https://USERNAME.github.io/REPONAME
```

> [!tip] اگر سایت ۴۰۴ داد
> تب **Actions** را چک کنید. workflow باید سبز شده باشد. اگر هنوز زرد است، صبر کنید (بار اول ۵-۸ دقیقه). اگر قرمز شد، متن ارور را بررسی کنید (معمولاً از deploy.yml است).

## ۴. گذاشتن محتوا روی کوارتز

همان‌طور که در اول متن گفتیم، کوارتز یادداشت‌های شما را به سایت تبدیل می‌کند. پوشهٔ `content` در فولدر کوارتز محل گذاشتن یادداشت‌هاست. هر یادداشتی که اینجا باشد، در سایت می‌آید.

### گام ۱: ساخت Vault ابسیدین

پیشنهاد من این است که داخل پوشهٔ `content` با ابسیدین یک Vault جدید بسازید:

1. ابسیدین را باز کنید → **Create new vault**
2. محل Vault: پوشهٔ `quartz/content`
3. نام: مثلاً `myblog`

این‌طوری مدیریت یادداشت‌ها و اعمال تغییرات روی آن ساده‌تر خواهد بود.

### گام ۲: ویرایش صفحهٔ اول

فایل `index.md` داخل پوشهٔ `content` صفحهٔ اول سایت شماست. اطلاعات اولیه و لینک دادن به سایر مطالب از طریق آن انجام می‌شود:

```markdown
---
title: خانه
---

# به سایت من خوش آمدید! 👋

اینجا یادداشت‌های من را می‌خوانید.

## مطالب اخیر

- [[اولین مطلب من]]
```

### گام ۳: نوشتن یادداشت

**Ctrl + N** → یادداشت جدید → بنویسید → **Ctrl + S**

### گام ۴: انتشار

```bash
npx quartz sync
```

به همین سادگی! هر بار بعد از نوشتن، کافیست دستور بالا را اجرا کنید که سایت خودبه‌خود آپدیت شود. بعد از این دیگر با گیتهاب هیچ کاری نخواهیم داشت. تغییرات را در کامپیوتر خودمان انجام می‌دهیم و نتیجه‌اش را روی دامنه می‌بینیم.

> [!danger] قبل از sync، ابسیدین را ببندید!
> وگرنه ارور `EBUSY: resource busy or locked` می‌گیرید، چون ابسیدین پوشهٔ content را قفل می‌کند.

### ساختن سایت به صورت لوکال (دیدن تغییرات لحظه‌ای)

برای دیدن سایت جدید و اعمال تغییرات همیشه لازم نیست که فایل‌ها را با گیتهاب سینک کنید و منتظر بمانید. اگر قصد دارید سایت را مدام تغییر بدهید و اثر تغییرات را ببینید، بهتر است با دستور زیر سایت را روی کامپیوتر خودتان بسازید:

```bash
npx quartz build --serve
```

خوبی‌اش این است که فقط با یک بار اجرا، سایت ساخته و مدام آپدیت می‌شود. یعنی به محض تغییر یک فایل، خود کوارتز بلافاصله سایت جدید را از نو می‌سازد و نمایش می‌دهد.

## ۵. مدیریت عکس‌ها (دانلود خودکار) 🖼️

وقتی مطلبی را از جایی کپی می‌کنید، عکس‌هایش معمولاً به صورت لینک خارجی (`![](https://...)`) هستند. دو راه دارید:

| روش | مزیت | عیب |
|-----|------|-----|
| نگه‌داشتن لینک خارجی | سریع، بدون دانلود | اگر سایت مبدأ از بین برود، عکس‌ها هم می‌پرند |
| دانلود و ذخیرهٔ محلی | پایدار برای همیشه | کار دستی خسته‌کننده |

خبر خوب: **نیازی به کار دستی نیست!** پلاگین **Local Images Plus** ابسیدین، خودش عکس‌های خارجی را دانلود می‌کند، در پوشهٔ `attachments` ذخیره می‌کند، و لینک را به لینک داخلی تبدیل می‌کند.

### گام ۱: نصب پلاگین

1. ابسیدین → **Settings** (چرخ‌دنده) → **Community plugins**
2. اگر اولین بار است، **Turn on community plugins** را بزنید
3. **Browse** → جستجو: **Local Images Plus**
4. **Install** → سپس **Enable**

### گام ۲: تنظیمات پلاگین

روی چرخ‌دندهٔ کنار Local Images Plus کلیک کنید:

| تنظیم | مقدار پیشنهادی |
|-------|---------------|
| **Folder for downloaded images** | `attachments` |
| **Process images automatically** | ✅ روشن |
| **Image name template** | `{{date}}_{{name}}` |

### گام ۳: استفاده

با روشن بودن **Process automatically**، هر بار که یادداشتی را باز می‌کنید، پلاگین خودش عکس‌های خارجی را دانلود و محلی می‌کند. یا به‌صورت دستی:

1. **Ctrl + P** (Command Palette)
2. بنویسید: **Local Images**
3. گزینهٔ **Process current page** را بزنید

**نتیجه:**

قبل:
```markdown
![[attachments/c31b55a82b7909b0ae929b2e370a2707_MD5.png]]
```

بعد:
```markdown
![[attachments/2026-07-22_pasted-image.png]]
```

> [!warning] نکتهٔ حجم
> بعد از محلی شدن عکس‌ها، آن‌ها داخل پوشهٔ `content` قرار می‌گیرند و با sync روی گیتهاب آپلود می‌شوند. پس حواستان به محدودیت **۱ گیگابایت** گیتهاب باشد (بخش «محدودیت حجم» را ببینید).

## ۶. فارسی‌سازی 🇮🇷

> [!note] تفاوت‌های مهم با نسخهٔ ۴ 🆕
> - فایل پیکربندی: `quartz.config.yaml` (نه `.ts`)
> - راست‌چین: **خودکار** با تنظیم `locale` (نیازی به دستکاری `renderPage.tsx` نیست!)
> - خط اول فایل CSS: `@use "./variables.scss" as *;` (نه `@use "./base.scss";`)

### ۶.۱ زبان و فونت

فایل **`quartz.config.yaml`** را باز کنید.

**زبان سایت** — دنبال مقدار `locale` بگردید و به `fa-IR` تغییر دهید:
```yaml
locale: fa-IR
```

**فونت** — نام فونت را مثل پایین تغییر دهید. برای اینکه فونت روی همهٔ دستگاه‌ها قابل مشاهده باشد، از فونت‌های گوگل انتخاب کنید. توصیهٔ من فونت `Vazirmatn` است:
```yaml
theme:
  typography:
    header: Vazirmatn
    body: Vazirmatn
    code: IBM Plex Mono
```

**آدرس سایت** — مطمئن باشید که مقدار `baseUrl` معادل آدرس سایت خودتان (بدون `http` یا `https`) باشد:
```yaml
baseUrl: zaadpro.github.io/myblog
```

### ۶.۲ راست‌چین (RTL) — خودکار!

> [!tip] خبر عالی 🎉
> در نسخهٔ ۵، راست‌چین **خودکار** است! در فایل `renderPage.tsx` این خط وجود دارد:
> ```tsx
> const direction = i18n(cfg.locale).direction ?? "ltr"
> ```
> یعنی وقتی `locale: fa-IR` باشد، خودش `dir="rtl"` را اعمال می‌کند. **هیچ دستکاری لازم نیست!** ✅

### ۶.۳ CSS فارسی

علاوه بر تنظیمات بالا، کد CSS باقی‌مانده را هم داخل `quartz/styles/custom.scss` بگذارید. من برای تنظیمات فارسی سایت، از این کد استفاده می‌کنم که احتمالاً به کار همه بیاید:

```scss
@use "./variables.scss" as *;

// put your custom CSS here!

html {
  font-family: Vazirmatn, sans-serif !important;
}

.breadcrumb-element p {
  margin: 0 .5rem 0 0;
  padding: 0;
  line-height: normal;
}

button#explorer .fold {
  opacity: .8;
  margin-left: 0 !important;
  margin-right: 0.5rem !important;
  transition: transform .3s;
}

.content-meta[show-comma="true"] > span:not(:last-child) {
  margin-left: 8px !important;
  margin-right: 0px !important;
}

.tags {
  padding-left: 0px !important;
  padding-right: 0px !important;
}

.folder-icon {
  margin-right: 0px !important;
  margin-left: 5px !important;
}

#explorer-content ul {
  padding-right: .7rem !important;
  padding-left: 0px !important;
}

#toc-content .depth-1 {
  padding: 0px !important;
  padding-right: 1rem !important;
}

#toc-content .depth-2 {
  padding: 0px !important;
  padding-right: 2rem !important;
}

#toc-content .depth-3 {
  padding: 0px !important;
  padding-right: 3rem !important;
}

li:has(> .folder-outer:not(.open)) > .folder-container > svg {
  transform: rotate(90deg) !important;
}

div.search.mobile-only {
  padding-right: 10px !important;
}

code {
  direction: ltr !important;
}
```

> [!danger] خط اول را پاک نکنید!
> خط `@use "./variables.scss" as *;` را **حتماً** نگه دارید. بدون آن build شکست می‌خورد.

تبریک مجدد! تا اینجای کار سایت شما به همراه یادداشت‌ها، خیلی شیک و مجلسی ساخته شده است. آنچه در ادامه می‌نویسم، دستکاری‌های اضافی‌ای است که لازم نیست؛ ولی تجربهٔ بهتری برای سایت می‌سازد.

## ۷. اضافه کردن عنوان و برچسب به متن

برای برچسب زدن به یادداشت‌ها، از **Frontmatter** استفاده می‌کنیم. یعنی یک بلوک اطلاعات در ابتدای هر یادداشت:

```markdown
---
title: عنوان نمایشی مطلب
tags:
  - آموزش
  - کوارتز
date: 2026-07-22
---

# اینجا متن اصلی یادداشت شروع می‌شود
```

> [!note] آن سه خط تیره `---` در ابتدا و انتها **حتماً** باید باشند.

- **`title`**: عنوانی که در سایت نمایش داده می‌شود
- **`tags`**: برچسب‌ها — باعث می‌شوند مطالب دسته‌بندی شوند
- **`date`**: تاریخ انتشار

> [!tip] پلاگین Templater
> برای جلوگیری از نوشتن کد تکراری بالا برای هر یادداشت، از پلاگین **Templater** ابسیدین استفاده کنید تا با یک کلیک، Frontmatter را به یادداشت جدید اضافه کند. البته که اگر برچسبی داخل متن باشد (مثل `#برچسب`)، خودبه‌خود به ابتدای مطلب شما اضافه می‌شود.

در `quartz.config.yaml`، بخش quartz-themes را پیدا کنید و مقدار `theme` را عوض کنید:

- source:

## ۹. اضافه کردن ویدیو (آپارات / گوگل‌درایو) 🎬

> [!danger] هرگز فایل ویدیو را در پوشهٔ `content` نگذارید!
> گیتهاب فقط ۱ گیگابایت فضا دارد و ویدیوها سریع آن را پر می‌کنند.

### آپارات (پیشنهادی ✅)

1. ویدیو را در **aparat.com** آپلود کنید (سطح دسترسی: **عمومی**)
2. کد **Embed** را کپی کنید
3. در یادداشت ابسیدین Paste کنید (نسخهٔ ریسپانسیو برای موبایل):

```html
<div style="position:relative; padding-bottom:56.25%; height:0; overflow:hidden;">
  <iframe
    src="https://www.aparat.com/video/video/embed/videohash/VIDEO_ID/vt/frame"
    style="position:absolute; top:0; left:0; width:100%; height:100%;"
    allowfullscreen>
  </iframe>
</div>
```

### گوگل‌درایو

```html
<iframe
  src="https://drive.google.com/file/d/FILE_ID/preview"
  style="width:100%; height:400px;"
  allow="autoplay">
</iframe>
```

> [!warning] گوگل‌درایو محدودیت پهنای باند دارد و به دلیل تحریم ممکن است برای بعضی کاربران لود نشود. برای مخاطب ایرانی، **آپارات** پایدارتر است.

## ۱۰. محدودیت حجم و هاست اختصاصی

### محدودیت حجم در github.io

حداکثر حجمی که گیتهاب در اختیار شما می‌گذارد **1GB** است. اگر تمرکز شما روی فایل‌های متنی است، باید چند میلیون یادداشت بنویسید تا نصف این فضا پر شود. اما اگر فایل‌های تصویری و ویدیویی زیادی دارید، می‌توانید از سرویس‌های رایگان دیگر —مثل **Gitlab** که 10GB حجم دارد— یا سرویس‌های داخلی استفاده کنید.

### قرار دادن سایت در هاست اختصاصی

اگر از سرویس‌های هاستینگ استفاده می‌کنید و دوست دارید سایت شخصی خودتان را روی آن‌ها قرار دهید، کافیست بدانید که کوارتز بعد از اجرای دستور `npx quartz build` فایل‌های HTML سایت را می‌سازد و آن‌ها را در پوشه‌ای به نام `public` قرار می‌دهد. پس کافیست برای داشتن سایت، این فایل‌ها را در هاست خودتان قرار دهید.

## 🔧 رفع مشکلات رایج

| مشکل | راه‌حل |
|------|--------|
| `Please tell me who you are` | `git config --global user.email "..."` و `git config --global user.name "..."` |
| `EBUSY: resource busy or locked` | ابسیدین را ببندید (پوشهٔ content را قفل کرده)، سپس sync بزنید |
| `EPERM: operation not permitted, rmdir` | کوارتز هنوز اجراست → با Ctrl+C متوقفش کنید یا از Task Manager دنبال Node بگردید و ببندید. یا ترمینال/VSCode را **Run as Administrator** کنید |
| `No such remote: 'origin'` | مشکلی نیست، مستقیم `git remote add origin ...` بزنید |
| سایت ۴۰۴ است | تب Actions را چک کنید؛ Source در Pages باید GitHub Actions باشد |
| build در Actions قرمز شد (`exit code 1`) | مطمئن شوید deploy.yml شامل `npx quartz plugin install` و branch `v5` و Node 24 است |
| `No space left on device` موقع create | پوشهٔ `%temp%` ویندوز را پاک کنید |
| `ENOENT ... package.json` | در پوشهٔ اشتباهی هستید؛ با `cd ..` به پوشهٔ اصلی `quartz` بروید |
| `Everything up-to-date` ولی سایت آپدیت نشده | احتمالاً commit به خاطر ارور identity ساخته نشده؛ identity را تنظیم و دوباره sync بزنید |
| فیلترینگ مانع git clone می‌شود | فیلترشکن را روشن/خاموش کنید |

## 📋 خلاصهٔ کل مسیر

```
نصب Node.js + Git + VSCode + اکانت گیتهاب
         ↓
git clone → cd quartz → npm i → npx quartz create (Obsidian)
         ↓
git config (معرفی خودتان) → git remote add → npx quartz sync --no-pull
         ↓
ساخت deploy.yml (v5 + plugin install + Node 24) → GitHub Pages: GitHub Actions
         ↓
npx quartz sync → سایت آنلاین! 🎉
         ↓
گذاشتن یادداشت‌ها در content (Vault ابسیدین)
         ↓
مدیریت عکس‌ها با Local Images Plus (دانلود خودکار)
         ↓
فارسی‌سازی (locale + فونت Vazirmatn + CSS) → RTL خودکار
         ↓
عنوان و برچسب (Frontmatter + Templater)
         ↓
تم زیبا (quartz-themes) → ویدیو در آپارات (کد embed)
         ↓
روتین: بستن ابسیدین → npx quartz sync → تمام! ✅
```
