## کوارتز چیه؟

![[attachments/c31b55a82b7909b0ae929b2e370a2707_MD5.png]]

کوارتز یک **Static Site Generator** رایگان است. سایتی که الان جلوی روی شماست، با کوارتز ساخته شده. به زبان ساده:

> **کوارتز یادداشت‌های ابسیدین را به عنوان ورودی می‌گیرد و به عنوان خروجی، یک سایت تحویل می‌دهد.**

به نظر من برای کسی که دنبال برنامه‌نویسی و سایت‌سازی از صفر نیست، کوارتز بهترین گزینه است. به خصوص که کوارتز جایزهٔ بهترین ابزار ابسیدین را هم گرفته است.

برای آشنایی بیشتر، قبل از شروع، این چند سایت را ببینید که با کوارتز ساخته شده‌اند:

- **[بلاگ کریستالین](https://blog.eledah.ir/)
- [وبلاگ فرد](https://ifard.ir/)
- [سایت کوارتز](https://quartz.jzhao.xyz)

### کوارتز در برابر راه‌های مشابه

کوارتز تنها Static Site Generator موجود نیست. **Hugo**، **Jekyll**، **MkDocs** و کلی سایت‌ساز رایگان دیگر هم در بازار موجودند. علاوه بر اینها، سینک کردن با وردپرس هم ممکن است. خود ابسیدین هم سرویسی به نام **Publish** دارد که یک سایت از Vault شما می‌سازد؛ اما به دلیل اینکه ماهی ۸ تا ۱۰ دلار برای کاربر عادی ایرانی آب می‌خورد، چندان به صرفه نیست. پس به جای راه گرانِ ساده، سراغ راه رایگانی می‌رویم که یک‌کم سخت‌تر است. البته نه خیلی. پیش‌بینی من از زمان راه‌اندازی کوارتز بین **۴۵ تا ۶۰ دقیقه** است. بعد از راه‌اندازی هم هر بار خیلی راحت با یک دستور ساده سایت خودبه‌خود آپدیت می‌شود و **ماهی ۸ تا ۱۰ دلار صرفه‌جویی می‌کنید**.

حالا چرا کوارتز؟ دلیل اصلی این است که **سازنده‌اش آن را به تن ابسیدین دوخته**. یعنی خودش کاربر ابسیدین بوده و کوارتز را برای انتشار آنلاین یادداشت‌هایش ساخته. آپدیت‌هایی که در آینده به آن اضافه می‌شود، در جهت نزدیکی بیشتر به تجربهٔ ابسیدین است. باقی سرویس‌ها —یا امثال **ویرگول** یا **بلاغفا**— توانایی تبدیل یادداشت به سایت را دارند؛ اما توجهی به ریزه‌کاری‌ها و جزئیات ابسیدین —مثل لینک‌های داخلی، استفاده از بک‌لینک یا برچسب، جستجوی حرفه‌ای و…— ندارند. تنظیم این ابزارها وقت و مهارت برنامه‌نویسی می‌خواهد که شاید هر کسی نداشته باشد. پس بهتر است سراغ ابزاری برویم که بیشترین همخوانی را با ابسیدین دارد.

> [!info] لیست ویژگی‌ها
> لیست کامل ویژگی‌های کوارتز را در [مستندات رسمی](https://quartz.jzhao.xyz) ببینید.

# 🟢 بخش اول: راه میانبر (Fork) — سریع و آسان

> در این روش، به جای ساختن سایت از صفر، یک **کپی آماده** از سایت فارسی‌سازی‌شدهٔ نویسندهٔ مرجع برمی‌دارید و مال خودتان می‌کنید. به این کار در گیتهاب **Fork** می‌گویند.

### Fork یعنی چی؟

در گیتهاب، Fork به این معنی است که شما یک کپی از کد دیگری در اکانت خودتان ایجاد می‌کنید. این کار به شما اجازه می‌دهد بدون تأثیر گذاشتن روی کد اصلی، تغییرات خودتان را اعمال کنید. مثل این است که یک کپی از یک پروژه را بردارید و روی آن جداگانه کار کنید.

> [!info] سایت نمونه
> سایت نمونهٔ راه میانبر در آدرس `eledah.ir/quartz` قابل مشاهده است. این سایت با ۱۷ تم رنگی مختلف آماده شده تا سایت‌ها در انتها شبیه هم نشوند.

# 🔵 بخش دوم: راه کامل (از صفر) — کنترل کامل

> در این روش، کوارتز را از صفر نصب می‌کنید و همه‌چیز را خودتان تنظیم می‌کنید. اگر برنامه‌نویسی بلد نیستید ولی می‌خواهید یاد بگیرید، این راه برای شماست.

---

## ۲.۱ راه‌اندازی کوارتز

اول از همه با کوارتز یک نسخهٔ محلی —نه اینترنتی— از سایتمان می‌سازیم تا در مرحله‌های بعدی آن را در قالب یک سایت اینترنتی بالا بیاوریم.

### گام ۱: دانلود کد کوارتز

دستور پایین را در ترمینال اجرا کنید تا کد کوارتز در دستگاه شما کپی شود. هرجایی که این کد اجرا شود، یک پوشه با نام `quartz` به همراه کدهای مورد نیازش ایجاد می‌شود.

```bash
git clone https://github.com/jackyzha0/quartz.git
```

> [!warning] ارور به خاطر فیلترینگ
> اگر اجرای کد بالا یا هر کد دیگری که اطلاعات را دانلود و آپلود می‌کند با خطا مواجه شد، ممکن است به خاطر تنظیمات اینترنت شما باشد. اگر فیلترشکن روشن است، خاموشش کنید یا برعکس.

### گام ۲: ورود به پوشه و نصب وابستگی‌ها

پوشهٔ کوارتز را با این دستور باز کنید:

```bash
cd quartz
```

سپس با دستور `npm i` نیازمندی‌های کوارتز را نصب کنید:

```bash
npm i
```

اگر حین اجرای دستور بالا با ارور یا هشدار خاصی مواجه شدید، محض محکم‌کاری دستور پایین را هم اجرا کنید:

```bash
npm audit fix --force
```

### گام ۳: ساخت پروژهٔ کوارتز

```bash
npx quartz create
```

> [!note] تفاوت مهم با نسخهٔ ۴ 🆕
> در نسخهٔ ۵، اول از شما می‌پرسد کدام **قالب (Template)** را می‌خواهید. گزینهٔ **Obsidian** را انتخاب کنید:
> ```
> ◆  Choose a template for your Quartz configuration
> │  ○ Default
> │  ● Obsidian        ← این را انتخاب کنید
> │  ○ TTRPG
> │  ○ Blog
> ```

سپس سؤال‌های بعدی:

**سؤال ۱ — مقداردهی محتوا:**
```
Choose how to initialize the content
│  ● Empty Quartz        ← Enter بزنید (دنگ و فنگ کمتری دارد)
│  ○ Copy an existing folder
│  ○ Symlink an existing folder
```

**سؤال ۲ — آدرس سایت (baseUrl):**
```
◆  Enter the base URL for your Quartz site
│  USERNAME.github.io/REPONAME
```

> [!warning] بدون `https://` و بدون `/` در آخر بنویسید. مثلاً: `zaadpro.github.io/myblog`

**سؤال ۳ — مدل لینک‌ها:** اگر مطمئن نیستید، اولی را انتخاب کنید. در غیر این‌صورت به بخش `Files and links` تنظیمات ابسیدین مراجعه کنید و ببینید جلوی `New link format` قبلاً چه تنظیماتی را انتخاب کرده‌اید.
```
Choose how Quartz should resolve links in your content
│  ● Treat links as shortest path
│  ○ Treat links as absolute path
│  ○ Treat links as relative path
```

> [!note] تفاوت مهم 🆕
> در نسخهٔ ۵، فایل پیکربندی **`quartz.config.yaml`** است (نه `quartz.config.ts` که در نسخهٔ ۴ بود). این نکته را تا آخر مطلب به خاطر بسپارید.

### گام ۴: تست محلی

تبریک! با تعیین تکلیف این موارد، سایت شما آماده است. حالا با اجرای دستور زیر، سایت شما ساخته می‌شود:

```bash
npx quartz build --serve
```

اگر همه‌چیز درست پیش رفته باشد، با رفتن به آدرس `http://localhost:8080` در مرورگر باید نسخهٔ اولیهٔ سایت خودتان را ببینید.

![[attachments/f2bd568322443354d25e9a04ae03fe13_MD5.png]]

> [!info] فایل‌های سایت
> فایل‌های HTML سایتی که کوارتز برای شما ساخته است، در پوشهٔ `public` قابل مشاهده است.

> [!warning] پذیرفتن درخواست فایروال
> در این مرحله ممکن است فایروال سیستم‌عامل شما درخواستی برای اجازه دادن یا ندادن به Node برای انجام یک سری عملیات بکند. حواستان باشد که با این درخواست **موافقت** کنید.

**متوقف کردن کوارتز:** تا وقتی که ترمینال باز است، کوارتز هم اجرا می‌شود. در این حالت کارهایی مثل تغییر اسم پوشه‌ها ممکن نیست. برای توقف، در ترمینال **Ctrl + C** را بزنید. از شما می‌پرسد «آیا مطمئنید؟». شما هم یک `y` جلویش بنویسید و Enter بزنید.

## ۲.۲ اتصال کوارتز به گیتهاب

تا اینجای کار سایت ساخته شده، منتها آنلاین و روی اینترنت نیست؛ فقط در دستگاه شماست. حالا می‌خواهیم این سایت را جایی بگذاریم که بشود با هر دستگاه متصل به اینترنت آن را دید. برای این کار اول کل فایل‌های کوارتز خودمان را روی گیتهاب می‌گذاریم و بعد به گیتهاب می‌گوییم که با این فایل‌ها، یک سایت تحویل ما بدهد.

### گام ۱: ساخت Repository

بعد از اینکه اکانت خودتان را در گیتهاب ساختید، با کلیک روی دکمهٔ **+** در سمت بالا راست صفحه و انتخاب `New repository` یک Repo جدید بسازید. برای اسم این Repo هر چه دوست داشتید —مثل `blog` یا `site` یا `website`— انتخاب کنید. تیکِ `Add a README file` را —اگر هست— بردارید و بدون تغییر باقی تنظیمات، `Create Repository` را بزنید.

### گام ۲: اتصال کوارتز به Repo خودتان

دوباره به ترمینال برگردید و این دستور را اجرا کنید:

```bash
git remote rm origin
```

> [!note] اگر ارور `No such remote: 'origin'` داد، مشکلی نیست. یعنی از قبل remote ای نبوده. مستقیم بروید سراغ دستور بعدی.

و بعد این:

```bash
git remote add origin https://github.com/USERNAME/REPONAME.git
```

> [!warning] حواستان باشد که در کد بالا، مقادیر `USERNAME` و `REPONAME` را با نام کاربری و اسم انتخابی Repo خودتان جایگزین کنید.

**این دو دستور چیکار می‌کنند؟** در حالت عادی، فایل کوارتزی که دانلود کرده‌اید به اکانت سازندهٔ اصلی‌اش متصل است. دستور اول این اتصال را قطع می‌کند و دستور دوم فایل‌های روی کامپیوتر را به اکانت خودتان متصل می‌کند.

### گام ۳: معرفی خودتان به Git

> [!danger] خیلی مهم!
> اگر این کار را نکنید، بعداً موقع sync با ارور `Please tell me who you are` مواجه می‌شوید و **commit ساخته نمی‌شود** (یعنی تغییرات هرگز به گیتهاب نمی‌رسند و سایت آپدیت نمی‌شود).

```bash
git config --global user.email "ایمیل‌تان@example.com"
git config --global user.name "نام‌تان"
```

### گام ۴: آپلود فایل‌ها روی گیتهاب

در نهایت هم دستور پایین را اجرا کنید تا فایل‌های روی کامپیوتر شما روی گیتهاب قرار بگیرد:

```bash
npx quartz sync --no-pull
```

بعد از سینک شدن فایل‌ها، اگر مشکلی پیش نیامده باشد، کوارتز در فضای ترمینال یک `Done` به نشانهٔ پایان کار به شما نشان می‌دهد. ✅

## ۲.۳ بالا آوردن سایت با گیتهاب

تا اینجای کار، کد کوارتز روی گیتهاب رفته است. حالا باید به گیتهاب بگوییم که سایت آنلاین را برای ما بسازد.

### گام ۱: ساخت فایل deploy.yml

به پوشهٔ زیر در فایل‌های کوارتز بروید و یک فایل با عنوان `deploy.yml` بسازید:

```
.github/workflows/
```

> [!note] مخفی بودن پوشه
> پوشهٔ `.github` ممکن است در کامپیوتر شما مخفی باشد. در File Explorer ویندوز، از تب **View** تیک **Hidden items** را بزنید.

داخل فایل `deploy.yml`، کد پایین را Paste و سپس آن را ذخیره کنید. (فایل را با VSCode یا Notepad یا هر ویرایشگر متن دیگری باز کنید.)

> [!danger] تفاوت حیاتی با نسخهٔ ۴ 🆕
> در نسخهٔ ۵، deploy.yml باید شامل مرحلهٔ **نصب پلاگین‌ها** (`npx quartz plugin install`) باشد و از **Node 24** و **actions v6** استفاده کند. بدون این مرحله، build در گیتهاب **شکست می‌خورد** (ارور `exit code 1`)، چون محیط گیتهاب خالی است و پلاگین‌های کوارتز ۵ در آن نصب نیستند. همچنین مقدار `branches` باید **`v5`** باشد (برای اطمینان، دستور `git branch` را بزنید).

```yaml
name: Deploy Quartz site to GitHub Pages

on:
  push:
    branches:
      - v5

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v6
        with:
          node-version: 24
      - name: Cache dependencies
        uses: actions/cache@v5
        with:
          path: ~/.npm
          key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
          restore-keys: |
            ${{ runner.os }}-node-
      - name: Cache Quartz plugins
        uses: actions/cache@v5
        with:
          path: .quartz/plugins
          key: ${{ runner.os }}-plugins-${{ hashFiles('quartz.lock.json') }}
          restore-keys: |
            ${{ runner.os }}-plugins-
      - name: Install Dependencies
        run: npm ci
      - name: Install Quartz plugins
        run: npx quartz plugin install
      - name: Build Quartz
        run: npx quartz build
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: public

  deploy:
    needs: build
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

### گام ۲: تنظیم GitHub Pages

به صفحهٔ Repo خودتان در سایت گیتهاب برگردید. داخل `Settings` بروید و از منوی سمت چپ `Pages` را انتخاب کنید. و برای `Source` گزینهٔ `GitHub Actions` را بزنید.

![[attachments/d8181de7493cc609e77093f0a29a5f80_MD5.jpg]]

### گام ۳: سینک نهایی

حالا با اجرای دستور زیر، یک دور دیگر محتویات کوارتز را با گیتهاب سینک می‌کنیم و گیتهاب سایت را برای ما می‌سازد:

```bash
npx quartz sync
```

بعد از چند دقیقه که گیتهاب سایت را ساخت، با مراجعه به این آدرس سایتتان را ببینید:

```
https://USERNAME.github.io/REPONAME
```

> [!tip] اگر سایت ۴۰۴ داد
> تب **Actions** را چک کنید. workflow باید سبز شده باشد. اگر هنوز زرد است، صبر کنید (بار اول ۵-۸ دقیقه). اگر قرمز شد، متن ارور را بررسی کنید (معمولاً از deploy.yml است).

## ۲.۴ فارسی‌سازی 🇮🇷

> [!note] تفاوت‌های مهم با نسخهٔ ۴ 🆕
> - فایل پیکربندی: `quartz.config.yaml` (نه `.ts`)
> - راست‌چین: **خودکار** با تنظیم `locale` (نیازی به دستکاری `renderPage.tsx` نیست!)
> - خط اول فایل CSS: `@use "./variables.scss" as *;` (نه `@use "./base.scss";`)

### ۲.۴.۱ زبان و فونت

فایل **`quartz.config.yaml`** را باز کنید.

**زبان سایت** — دنبال مقدار `locale` بگردید و به `fa-IR` تغییر دهید:
```yaml
locale: fa-IR
```

**فونت** — نام فونت را مثل پایین تغییر دهید. برای اینکه فونت روی همهٔ دستگاه‌ها قابل مشاهده باشد، از فونت‌های گوگل انتخاب کنید. توصیهٔ من فونت `Vazirmatn` است:
```yaml
theme:
  typography:
    header: Vazirmatn
    body: Vazirmatn
    code: IBM Plex Mono
```

**آدرس سایت** — مطمئن باشید که مقدار `baseUrl` معادل آدرس سایت خودتان (بدون `http` یا `https`) باشد:
```yaml
baseUrl: zaadpro.github.io/myblog
```

### ۲.۴.۲ راست‌چین (RTL) — خودکار!

> [!tip] خبر عالی 🎉
> در نسخهٔ ۵، راست‌چین **خودکار** است! در فایل `renderPage.tsx` این خط وجود دارد:
> ```tsx
> const direction = i18n(cfg.locale).direction ?? "ltr"
> ```
> یعنی وقتی `locale: fa-IR` باشد، خودش `dir="rtl"` را اعمال می‌کند. **هیچ دستکاری لازم نیست!** ✅
>
> (در نسخهٔ ۴ باید دستی در `renderPage.tsx` خط `<html lang={lang}>` را به `<html dir="rtl" lang={lang}>` تغییر می‌دادید. اگر همچنان برای راست‌چین کردن مشکل داشتید، به گفت‌وگوهای جامعهٔ کوارتز نگاهی بیندازید.)

### ۲.۴.۳ CSS فارسی

علاوه بر تنظیمات بالا، کد CSS باقی‌مانده را هم داخل `quartz/styles/custom.scss` بگذارید. من برای تنظیمات فارسی سایت، از این کد استفاده می‌کنم که احتمالاً به کار همه بیاید:

```scss

}

  margin: 0 .5rem 0 0;
  padding: 0;

  margin-left: 0 !important;

  margin-left: 8px !important;
  margin-right: 0px !important;
}

.tags {
  padding-left: 0px !important;
  padding-right: 0px !important;
}

.folder-icon {
  margin-right: 0px !important;
  margin-left: 5px !important;
}

#explorer-content ul {
  padding-right: .7rem !important;
  padding-left: 0px !important;
}

#toc-content .depth-1 {
  padding: 0px !important;
  padding-right: 1rem !important;
}

#toc-content .depth-2 {
  padding: 0px !important;
  padding-right: 2rem !important;
}

#toc-content .depth-3 {
  padding: 0px !important;
  padding-right: 3rem !important;
}

li:has(> .folder-outer:not(.open)) > .folder-container > svg {
  transform: rotate(90deg) !important;
}

div.search.mobile-only {
  padding-right: 10px !important;
}

  direction: ltr !important;
}
```

> [!danger] خط اول را پاک نکنید!
> خط `@use "./variables.scss" as *;` را **حتماً** نگه دارید. بدون آن build شکست می‌خورد.

> [!info] سایر تنظیمات
> سایر تنظیمات سایت —مثل عنوان، رنگ‌ها و چیدمان— هم در همین فایل `quartz.config.yaml` قابل تنظیم است. (در نسخهٔ ۴، چیدمان در فایل جداگانهٔ `quartz.layout.ts` بود؛ در نسخهٔ ۵ همه‌چیز داخل همان yaml است.)

تبریک مجدد! تا اینجای کار سایت شما به همراه یادداشت‌ها، خیلی شیک و مجلسی ساخته شده است. آنچه در ادامه می‌نویسم، دستکاری‌های اضافی‌ای است که لازم نیست؛ ولی تجربهٔ بهتری برای سایت می‌سازد.

# 📝 بخش سوم: کار با محتوا (مشترک هر دو راه)

## ۳.۱ گذاشتن محتوا

همان‌طور که در اول متن گفتیم، کوارتز یادداشت‌های شما را به سایت تبدیل می‌کند. پوشهٔ **`content`** در فولدر کوارتز محل گذاشتن یادداشت‌هاست. هر یادداشتی که اینجا باشد، در سایت می‌آید.

پیشنهاد من این است که داخل پوشهٔ `content` با ابسیدین یک Vault جدید بسازید و یادداشت‌هایی را که می‌خواهید آنلاین باشند —به همراه تصاویرشان— به داخل آن بیاورید. این‌طوری مدیریت یادداشت‌ها و اعمال تغییرات روی آن ساده‌تر خواهد بود.

فایل **`index.md`** داخل پوشهٔ `content` هم صفحهٔ اول سایت شماست. اطلاعات اولیه و لینک دادن به سایر مطالب از طریق آن انجام می‌شود. اگر می‌خواهید عنوان نمایشی آن را عوض کنید، بخش «اضافه کردن عنوان و برچسب» را ببینید.

بعد از اضافه کردن یادداشت‌ها، کافیست این دستور را بار دیگر در ترمینال اجرا کنید:

```bash
npx quartz sync
```

به همین سادگی! هر بار بعد از نوشتن، کافیست دستور بالا را اجرا کنید که سایت خودبه‌خود آپدیت شود. بعد از این دیگر با گیتهاب هیچ کاری نخواهیم داشت. اصلاً نیازی نیست که به آن سر بزنیم. تغییرات را در کامپیوتر خودمان انجام می‌دهیم و نتیجه‌اش را روی دامنه می‌بینیم.

### ساختن سایت به صورت لوکال

برای دیدن سایت جدید و اعمال تغییرات همیشه لازم نیست که فایل‌ها را با گیتهاب سینک کنید و منتظر بمانید. اگر قصد دارید سایت را مدام تغییر بدهید و اثر تغییرات را ببینید، بهتر است با دستور زیر سایت را روی کامپیوتر خودتان بسازید:

```bash
npx quartz build --serve
```

خوبی‌اش این است که فقط با یک بار اجرا، سایت ساخته و مدام آپدیت می‌شود. یعنی به محض تغییر یک فایل، خود کوارتز بلافاصله سایت جدید را از نو می‌سازد و نمایش می‌دهد.

## ۳.۲ مدیریت عکس‌ها (دانلود خودکار) 🖼️

وقتی مطلبی را از جایی کپی می‌کنید، عکس‌هایش معمولاً به صورت لینک خارجی (`![](https://...)`) هستند. دو راه دارید:

| روش | مزیت | عیب |
|-----|------|-----|
| نگه‌داشتن لینک خارجی | سریع، بدون دانلود | اگر سایت مبدأ از بین برود، عکس‌ها هم می‌پرند |
| دانلود و ذخیرهٔ محلی | پایدار برای همیشه | کار دستی خسته‌کننده |

خبر خوب: **نیازی به کار دستی نیست!** پلاگین **Local Images Plus** ابسیدین، خودش عکس‌های خارجی را دانلود می‌کند، در پوشهٔ `attachments` ذخیره می‌کند، و لینک را به لینک داخلی تبدیل می‌کند.

### نصب و تنظیم

1. ابسیدین → **Settings** → **Community plugins** → **Browse**
2. جستجو: **Local Images Plus** → **Install** → **Enable**
3. روی چرخ‌دندهٔ پلاگین کلیک کنید:

| تنظیم | مقدار پیشنهادی |
|-------|---------------|
| **Folder for downloaded images** | `attachments` |
| **Process images automatically** | ✅ روشن |

با روشن بودن **Process automatically**، هر بار که یادداشتی را باز می‌کنید، پلاگین خودش عکس‌های خارجی را دانلود و محلی می‌کند. یا دستی: **Ctrl + P** → بنویسید **Local Images** → **Process current page**.

**نتیجه:**

قبل:
```markdown
![[attachments/c31b55a82b7909b0ae929b2e370a2707_MD5.png]]
```

بعد:
```markdown
![[attachments/2026-07-22_pasted-image.png]]
```

> [!warning] نکتهٔ حجم
> بعد از محلی شدن عکس‌ها، آن‌ها داخل پوشهٔ `content` قرار می‌گیرند و با sync روی گیتهاب آپلود می‌شوند. پس حواستان به محدودیت **۱ گیگابایت** گیتهاب باشد.

## ۳.۳ اضافه کردن عنوان و برچسب به متن

برای برچسب زدن به یادداشت‌ها، از **Frontmatter** استفاده می‌کنیم. یعنی یک بلوک اطلاعات در ابتدای هر یادداشت:

```markdown
---
title: عنوان نمایشی مطلب
tags:
  - آموزش
  - کوارتز
date: 2026-07-22
---

# اینجا متن اصلی یادداشت شروع می‌شود
```

> [!note] آن سه خط تیره `---` در ابتدا و انتها **حتماً** باید باشند.

- **`title`**: عنوانی که در سایت نمایش داده می‌شود
- **`tags`**: برچسب‌ها — باعث می‌شوند مطالب دسته‌بندی شوند
- **`date`**: تاریخ انتشار

> [!tip] پلاگین Templater
> برای جلوگیری از نوشتن کد تکراری بالا برای هر یادداشت، از پلاگین **Templater** ابسیدین استفاده کنید تا با یک کلیک، Frontmatter را به یادداشت جدید اضافه کند. البته که اگر برچسبی داخل متن باشد (مثل `#برچسب`)، خودبه‌خود به ابتدای مطلب شما اضافه می‌شود.

---

## ۳.۴ اضافه کردن ویدیو (آپارات / گوگل‌درایو) 🎬

> [!danger] هرگز فایل ویدیو را در پوشهٔ `content` نگذارید!
> گیتهاب فقط ۱ گیگابایت فضا دارد و ویدیوها سریع آن را پر می‌کنند.

### آپارات (پیشنهادی ✅)

1. ویدیو را در **aparat.com** آپلود کنید (سطح دسترسی: **عمومی**)
2. کد **Embed** را کپی کنید
3. در یادداشت ابسیدین Paste کنید (نسخهٔ ریسپانسیو برای موبایل):

```html
<div style="position:relative; padding-bottom:56.25%; height:0; overflow:hidden;">
  <iframe
    src="https://www.aparat.com/video/video/embed/videohash/VIDEO_ID/vt/frame"
    style="position:absolute; top:0; left:0; width:100%; height:100%;"
    allowfullscreen>
  </iframe>
</div>
```

### گوگل‌درایو

```html
<iframe
  src="https://drive.google.com/file/d/FILE_ID/preview"
  style="width:100%; height:400px;"
  allow="autoplay">
</iframe>
```

> [!warning] گوگل‌درایو محدودیت پهنای باند دارد و به دلیل تحریم ممکن است برای بعضی کاربران لود نشود. برای مخاطب ایرانی، **آپارات** پایدارتر است.

# 🌐 بخش چهارم: اتصال دامنهٔ شخصی

> تا اینجا سایت شما با آدرس `USERNAME.github.io/REPONAME` در دسترس است. حالا اگر یک دامنهٔ شخصی دارید (مثلاً `myblog.ir` یا `myblog.com`)، می‌توانید آن را به سایتتان وصل کنید.

## ۴.۱ خرید دامنه

اگر هنوز دامنه ندارید:
- برای دامنهٔ **`.ir`**: از سایت **ایرنیک** (nic.ir) یا ثبت‌کننده‌های داخلی (مثل ایرنیک، پارس‌دیتا، میزبان‌فا) بخرید.
- برای دامنهٔ **`.com`** و بین‌المللی: از ثبت‌کننده‌های خارجی یا داخلی که دامنهٔ بین‌المللی می‌فروشند.

> [!info] نکته
> بعد از خرید، به **پنل مدیریت دامنه** دسترسی دارید. جایی که می‌توانید DNS را تنظیم کنید. این پنل را پیدا کنید چون در مرحلهٔ ۴.۳ لازم است.

## ۴.۲ تنظیم در گیتهاب

**گام ۱:** به صفحهٔ Repo خودتان در گیتهاب بروید → **Settings** → **Pages**

**گام ۲:** در بخش **Custom domain**، دامنهٔ خودتان را وارد کنید:
```
myblog.ir
```
یا
```
www.myblog.com
```

**گام ۳:** دکمهٔ **Save** را بزنید.

> [!note] چه اتفاقی می‌افتد؟
> گیتهاب یک فایل به نام **`CNAME`** در Repo شما می‌سازد که داخلش آدرس دامنهٔ شماست. این فایل به گیتهاب می‌گوید که سایت را روی این دامنه سرو کند.

**گام ۴:** صبر کنید تا گیتهاب DNS را بررسی کند. ممکن است چند دقیقه طول بکشد.

## ۴.۳ تنظیم DNS در پنل دامنه

حالا باید به پنل مدیریت دامنه‌تان بروید و رکوردهای DNS را تنظیم کنید. دو حالت دارد:

### حالت الف: دامنهٔ اصلی (مثلاً `myblog.ir` بدون www)

باید **۴ رکورد A** بسازید که به IP های گیتهاب اشاره کنند:

| Type | Host/Name | Value |
|------|-----------|-------|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |

### حالت ب: زیردامنهٔ www (مثلاً `www.myblog.com`)

باید یک **رکورد CNAME** بسازید:

| Type | Host/Name | Value |
|------|-----------|-------|
| CNAME | `www` | `USERNAME.github.io` |

> [!tip] بهترین حالت
> هر دو را تنظیم کنید (۴ رکورد A برای دامنهٔ اصلی + ۱ رکورد CNAME برای www). سپس در گیتهاب، تیک **Enforce HTTPS** را بزنید تا سایت با `https` باز شود.

> [!warning] صبر کنید!
> تغییرات DNS ممکن است از چند دقیقه تا **۴۸ ساعت** طول بکشد تا در همهٔ دنیا اعمال شود (به این فرآیند **propagation** می‌گویند). معمولاً در ایران چند ساعته انجام می‌شود. اگر سایت باز نشد، نگران نباشید و چند ساعت صبر کنید.

## ۴.۴ تغییر baseUrl در کوارتز

> [!danger] مهم!
> بعد از عوض کردن دامنه، باید مقدار `baseUrl` را در فایل پیکربندی عوض کنید. وگرنه لینک‌های داخلی سایت خراب می‌شوند.

**در راه کامل (نسخهٔ ۵):** فایل `quartz.config.yaml`:
```yaml
baseUrl: myblog.ir
```

**در راه میانبر (نسخهٔ ۴):** فایل `quartz.config.ts`:
```typescript
baseUrl: "myblog.ir",
```

> بدون `http` یا `https` و بدون `/` در آخر.

سپس:
- **راه کامل:** `npx quartz sync`
- **راه میانبر:** Commit و Push در Github Desktop

# 🔧 بخش ششم: رفع مشکلات رایج

## ارور `EBUSY: resource busy or locked` 🔒

این ارور را موقع `npx quartz sync` می‌بینید:

```
[Error: EBUSY: resource busy or locked, rmdir 'D:\myblog\quartz\content']
```

### معنی‌اش چیست؟

کوارتز موقع sync، پوشهٔ `content` را موقتاً جابه‌جا می‌کند (backup می‌گیرد). اما **برنامهٔ دیگری** این پوشه را باز و قفل کرده و ویندوز اجازهٔ جابه‌جایی نمی‌دهد.

### دلایل (به ترتیب احتمال):

| # | دلیل | چطور بفهمیم؟ |
|---|------|-------------|
| ۱ | **ابسیدین باز است** و Vault را روی `content` باز کرده | محتمل‌ترین دلیل! |
| ۲ | `npx quartz build --serve` هنوز اجراست | ترمینالی باز است که سرور محلی دارد |
| ۳ | VSCode پوشهٔ content را باز دارد | VSCode باز است |
| ۴ | File Explorer داخل پوشهٔ content باز است | پنجره‌ای باز است |
| ۵ | آنتی‌ویروس در حال اسکن پوشه است | نادر |

### راه‌حل‌ها (به ترتیب):

**راه‌حل ۱: ابسیدین را کامل ببندید**
- روی آیکون ابسیدین در Taskbar راست‌کلیک → **Close**
- یا **Ctrl + Shift + Esc** (Task Manager) → دنبال **Obsidian** بگردید → **End Task**

**راه‌حل ۲: سرور محلی را متوقف کنید**
- در ترمینالی که `npx quartz build --serve` اجراست، **Ctrl + C** بزنید

**راه‌حل ۳: VSCode و Explorer را ببندید**

**راه‌حل ۴: اگر باز هم نشد، سیستم را ریستارت کنید**

**راه‌حل ۵ (جایگزین): به جای sync، دستی push کنید**

این روش اصلاً نیازی به جابه‌جایی پوشهٔ content ندارد:

```bash
git add .
git commit -m "update content"
git push origin v5
```

> [!tip] قانون طلایی
> **قبل از هر `npx quartz sync`، ابسیدین را ببندید.** این ساده‌ترین راه جلوگیری از EBUSY است.

### پیدا کردن برنامهٔ قفل‌کننده (روش پیشرفته)

اگر نمی‌دانید کدام برنامه پوشه را قفل کرده:

1. کلید `Win + R` → بنویسید `resmon` → Enter
2. تب **CPU** → بخش **Associated Handles**
3. در جستجو بنویسید: `content`
4. ببینید کدام برنامه آن را باز دارد → راست‌کلیک → **End Process**

## ارور `Please tell me who you are` 👤

```
Author identity unknown
*** Please tell me who you are.
fatal: unable to auto-detect email address
```

### معنی‌اش چیست؟

Git نمی‌داند شما کی هستید و نمی‌تواند commit بسازد. در نتیجه تغییرات به گیتهاب نمی‌رسند.

### راه‌حل:

```bash
git config --global user.email "ایمیل‌تان@example.com"
git config --global user.name "نام‌تان"
```

سپس دوباره `npx quartz sync` بزنید.

> [!warning] نکتهٔ مهم
> اگر قبلاً sync زدید و `Everything up-to-date` دیدید ولی سایت آپدیت نشد، احتمالاً به خاطر همین ارور بوده که commit ساخته نشده. بعد از تنظیم identity، دوباره sync بزنید.

---

## ارور `EPERM: operation not permitted, rmdir` 🚫

```
Error: EPERM: operation not permitted, rmdir
```

### معنی‌اش چیست؟

ترمینال شما دسترسی‌های لازم به فایل‌های کوارتز را ندارد. این ارور می‌تواند چند ریشه داشته باشد:

### ریشهٔ ۱: کوارتز هنوز در حال اجراست

کوارتز به ترمینال اجازهٔ دست بردن در فایل‌ها را نمی‌دهد.

**راه‌حل:** یا با `Ctrl + C` آن را در ترمینال متوقف کنید یا با Task Manager دنبال Node بگردید و آن را ببندید.

### ریشهٔ ۲: ویندوز اجازه نمی‌دهد

**راه‌حل الف:** ترمینال/VSCode را **Run as Administrator** کنید:
- روی آیکون ترمینال/VSCode راست‌کلیک → **Run as administrator**

**راه‌حل ب:** با راست‌کلیک روی پوشهٔ quartz → **Properties** → تب **Security** → اجازهٔ دسترسی **Full control** را به کاربر عادی بدهید.

## ارور `No space left on device` 💾

```
error: unable to create file ...: No space left on device
```

### معنی‌اش چیست؟

پوشهٔ Temp ویندوز پر شده. معمولاً موقع `npx quartz create` و نصب پلاگین quartz-themes رخ می‌دهد.

### راه‌حل:

1. کلید `Win + R` → بنویسید `%temp%` → Enter
2. همه فایل‌ها را Select All (Ctrl+A) → Delete
3. اگر بعضی پاک نشدند، Skip بزنید
4. دوباره دستور را اجرا کنید

---

## ارور `ENOENT: no such file or directory, package.json` 📂

```
Error: ENOENT: no such file or directory, open 'D:\myblog\quartz\content\package.json'
```

### معنی‌اش چیست؟

در پوشهٔ اشتباهی هستید! به ابتدای خط ترمینال نگاه کنید. اگر `D:\myblog\quartz\content>` می‌بینید، یعنی داخل پوشهٔ `content` هستید.

### راه‌حل:

```bash
cd ..
```

حالا باید `D:\myblog\quartz>` را ببینید. سپس دستورتان را اجرا کنید.

> [!info] قانون
> هر دستوری که با `npx quartz ...` شروع می‌شود (مثل `sync`، `build`، `create`) را **همیشه** در پوشهٔ اصلی `quartz` اجرا کنید، نه داخل `content`.

## ارور `No such remote: 'origin'` 🔗

```
error: No such remote: 'origin'
```

### معنی‌اش چیست؟

از قبل remote ای به نام origin وجود نداشته. مشکلی نیست.

### راه‌حل:

مستقیم بروید سراغ دستور بعدی:
```bash
git remote add origin https://github.com/USERNAME/REPONAME.git
```

## جدول خلاصهٔ ارورها

| ارور | راه‌حل سریع |
|------|------------|
| `EBUSY: resource busy or locked` | ابسیدین را ببندید، سپس sync |
| `Please tell me who you are` | `git config --global user.email/name` |
| `EPERM: operation not permitted` | Run as Administrator یا Properties→Security |
| `No space left on device` | پوشهٔ `%temp%` را پاک کنید |
| `ENOENT ... package.json` | با `cd ..` به پوشهٔ اصلی بروید |
| `No such remote: 'origin'` | مشکلی نیست، `git remote add` بزنید |
| سایت ۴۰۴ | Actions را چک کنید، Source = GitHub Actions |
| build قرمز (`exit code 1`) | deploy.yml را با نسخهٔ v5 جایگزین کنید |
| `Everything up-to-date` ولی آپدیت نشده | identity را تنظیم و دوباره sync بزنید |
| فیلترینگ مانع git clone می‌شود | فیلترشکن را روشن/خاموش کنید |

# 📦 بخش هفتم: محدودیت حجم و هاست اختصاصی

## محدودیت حجم در github.io

حداکثر حجمی که گیتهاب در اختیار شما می‌گذارد **1GB** است. اگر تمرکز شما روی فایل‌های متنی است، باید چند میلیون یادداشت بنویسید تا نصف این فضا پر شود. اما اگر فایل‌های تصویری و ویدیویی زیادی دارید و ممکن است از این حد عبور کنید، می‌توانید از سرویس‌های رایگان دیگر —مثل **Gitlab** که 10GB حجم دارد— یا سرویس‌های داخلی استفاده کنید.

## قرار دادن سایت در هاست اختصاصی

اگر از سرویس‌های هاستینگ استفاده می‌کنید و دوست دارید سایت شخصی خودتان را روی آن‌ها قرار دهید، کافیست بدانید که کوارتز بعد از اجرای دستور `npx quartz build` فایل‌های HTML سایت را می‌سازد و آن‌ها را در پوشه‌ای به نام `public` قرار می‌دهد. پس کافیست برای داشتن سایت، این فایل‌ها را در هاست خودتان قرار دهید.

> [!info] تنظیمات هاست
> تنظیمات هاست برای میزبانی از کوارتز را در مستندات سایت مرجع ببینید.

```
ساخت اکانت گیتهاب + نصب Github Desktop
         ↓

         ↓
Settings → Pages → GitHub Actions

Environments → پاک‌سازی
         ↓
Github Desktop → Clone Repository
         ↓
باز کردن content در ابسیدین → نوشتن
         ↓
Commit → Push → تیک سبز ✅
         ↓
شخصی‌سازی (تم، عنوان، baseUrl)
         ↓
اتصال دامنه (Custom domain + DNS + baseUrl)
```

## راه کامل (از صفر):
```
نصب Node.js + Git + VSCode + اکانت گیتهاب
         ↓
git clone → cd quartz → npm i → npx quartz create (Obsidian)
         ↓
git config (معرفی خودتان) → git remote add → npx quartz sync --no-pull
         ↓
ساخت deploy.yml (v5 + plugin install + Node 24) → GitHub Pages: GitHub Actions
         ↓
npx quartz sync → سایت آنلاین! 🎉
         ↓
گذاشتن یادداشت‌ها در content (Vault ابسیدین)
         ↓
مدیریت عکس‌ها با Local Images Plus (دانلود خودکار)
         ↓
فارسی‌سازی (locale + فونت Vazirmatn + CSS) → RTL خودکار
         ↓
عنوان و برچسب (Frontmatter + Templater)
         ↓
تم زیبا (quartz-themes) → ویدیو در آپارات (کد embed)
         ↓
اتصال دامنه (Custom domain + DNS + baseUrl)
         ↓
روتین: بستن ابسیدین → npx quartz sync → تمام! ✅
```
